Changed
- **Includes everything in 0.9.1 and 0.9.2.** Upgrading from 0.9.0, read
  those sections too: they turn Electrum and Esplora onion and I2P
  publishing into opt-in switches, add the `{datadir}/network` marker, and
  ask a datadir that connected the bad same-block re-spend to re-sync.
- **Store schema 30: spends are recorded in a spend delta.** Every spend
  is a note under `store/spent.delta/`, checkpointed every 10 minutes or
  at 2,000,000 open notes and folded into `spent.body` in the background,
  so a torn write can no longer lose a committed spend. Opening a 0.9.x
  datadir (schema 26 or 27) upgrades it in place with no reindex: open
  reads `spent.body` once and adopts it as the first delta generation.
  **A 0.9.x binary will not open the datadir afterwards.** Each checkpoint
  logs `store: spend delta …`, and `ibd: perf_full` gains
  `spend_room_wait_ms`. After 60 failed checkpoints in a row confirm stops
  waiting at the open-note cap and returns a store error instead of
  stalling.
- **An unknown conf key is a startup error.** A misspelled key used to be
  warned about and ignored, so a typo in a privacy or security setting
  failed open. The error names the file, line, and key.
- **A held P2P port fails startup with Core's bind error** (`Unable to bind
  to <addr> on this computer. rbitcoin is probably already running.`).
  Every listener on Windows sets `SO_EXCLUSIVEADDRUSE`, as in Core.
- **A restart with a known peers book dials it before the DNS seeds.** As
  in Core, the node waits 11 s (5 min with 1,000 or more rows) and asks the
  seeds only if fewer than two outbound full-relay peers are up. An empty
  book still asks at once. Start skips the fixed-seed table when the book
  already covers every reachable net.
- **A private broadcast is retried if it does not come back.** If no
  normal peer echoes the transaction, it is sent privately again to two
  peers every 2 to 3.5 minutes, up to 1,000 rounds, until it confirms.
- **Electrum and Stratum v2 connect and disconnect lines log at DEBUG,**
  so a reconnecting client cannot fill the log. Their max-connection
  refusals stay WARN. The RPC max-connections, self-connection, and
  header-reject lines are each logged at most once a second per thread.
- **Some IBD diagnostic lines are gone:** the "download gate closed" and
  15-second "tip stall" warnings, the slow confirm-write phase breakdown,
  and the rehydrate summaries.
- **The SV2 template provider uses the November 2026 Stratum crates.** Wire
  bytes are unchanged. A `SubmitSolution` time-window log line now says
  `ntime`. The AES-GCM crates leave the build.
- **IBD uses less memory and CPU.** At a ~962k tip, the confirmed-hash set
  (~66 MiB), the peer readers' header map (41–82 MiB), and most of the
  resume header index (~210 MiB → ~48 MiB) are gone, and each block's raw
  bytes are dropped as soon as they are decoded (25–60 MB per lookup
  wave). The body queue, in-flight tracking, and spend reads were reworked
  so a status tick, rewind, or stuck-gate check no longer scans every
  queued row. Removing a mempool transaction no longer rescans every
  accept time. Announcing a new tip reads parents from stored headers, not
  rebuilt blocks.
- **The open `tx.head` segment lives in memory.** It is written once at
  clean shutdown. After a crash, open rebuilds only that tail from
  `txid.body` instead of the whole index.
- **Core's tests run from Bitcoin Core master `e211dd01`**, after v32.1:
  `script_tests` 1280/1280, `tx_valid` 122/122, `tx_invalid` 97/97, plus
  the new functional checks. Release binaries are still compared against
  v32.1. The functional harness keeps Core's message text and counts in
  its shim and log map, so the node changes only where a peer would miss
  a block or transaction or a documented RPC code would differ.
- **Docs follow the code.** The Core, Fulcrum, Hornet, satd, and BLVM
  comparison pages, the Hornet rule cross-reference (35-rule spec), and the
  living operator docs were brought up to date. One measured mainnet
  catch-up: a ThinkPad X1 Carbon Gen 13 (Core Ultra 7 258V, 32 GiB, Crucial
  T500 2 TB) reached height 975,252 in 9 h 51 min and left IBD in
  10 h 12 min.
- **Tests and CI.** The test guide names four layers; peer and RPC tests
  wait on conditions instead of sleeps; the default suite is faster.
  Nightly mutants found gaps that were closed with journeys or by deleting
  unobservable compares. Fixed-width store reads go through one typed
  helper, so an out-of-range window does not compile. A dozen flaky or
  macOS-only test failures were fixed.
- **Confirm queues measure a batch's wire size once.** The load, script,
  and write queue accounting each walked every transaction of every block
  in a batch (`Block::total_size`) to log its wire bytes, about four walks
  per batch. Load now measures it once and the batch carries it.
- **Sealed `tx.head` probes keep their MPHF page buffers.** Each probe of
  a sealed segment's FdOnly `g` allocated and zeroed a pool of up to 128
  page buffers (512 KiB), then zeroed each buffer again before its read.
  The resolve thread now keeps the pool between waves, and a page buffer is
  not zeroed before the read that fills it (a short read already re-reads
  the whole page).
- **A spend delta checkpoint reads merge records in one completion-session batch.**
  The merge used to `pread` each span on its own. A mainnet checkpoint
  does that for every sealed page that already has a record, on the order
  of a few hundred thousand reads, and confirm waits out the whole
  checkpoint. Those spans now go out together, at ring depth 128, into
  the one buffer the merge already sizes. Records that touch in a segment
  still share one span, so the gap between them is not read. `merge_reads`
  still counts spans. `RBITCOIN_IO=pread`, and a ring that will not open,
  keep the libc pread bulk fallback.
- **Confirm reads spend-delta records in one completion-session batch.**
  A lookup that missed the open notes used to `pread` each page's record
  on its own. Those records now go out together, at ring depth 128, on
  the same session as the `spent.body` peeks. Records that touch in a
  segment share one span. `RBITCOIN_IO=pread`, and a ring that will not
  open, keep the libc pread bulk fallback. A folded page with no record
  is still not read from the delta, and a RAM note is still not read.
- **A doc comment left on the wrong item fails `qc`.** Inserting an item
  between a `///` block or an attribute and its item, or deleting an item
  and keeping its block, moves that block onto another item with no
  warning. `./scripts/doc-attach.sh` compares a pull request with its base
  and fails on both. Three such blocks on master are back on their items,
  one of them a `#[doc(hidden)]` that had moved from a public function to a
  private one.
- `--external-ip` and `external_ip=` accept explicit public P2P ports for IPv4, bracketed IPv6, and Tor v3 onion addresses.
- Append `=onion` to a P2P listen address to dedicate it to Tor forwarding and keep source-IP permission rules on ordinary listeners.
- **Inbound loopback loses source-IP grants when onion or I2P forwarding is on.** That is `--listen-onion` with no `=onion` bind, `--i2p-accept-incoming`, or an onion `--external-ip` with no marked listener. A local wallet under `noban,relay,download@127.0.0.1` loses those grants; v0.9.2 applied them. A `--net-permission-bind` on that port keeps them, and it applies them to every inbound peer on that listener, including a forwarded onion or I2P peer. Put the wallet grant on a listener the forwarder does not use. An onion `--external-ip` with no marked listener also withholds self-announcements from inbound loopback. `--listen-onion` alone, or `--i2p-accept-incoming` alone, still announces that overlay address.
- **Confirm load chooses each parent's plan pin in one pass.** It walked
  the batch's parents three times (batch pins, in-flight creates, recent
  stamped pins), checking a growing map each time. One pass now takes the
  first source that holds the parent, into a map sized for the batch.
  `ibd: perf_full` drops `load_pin_recent_outs_ms`, the third walk's wall,
  which `load_thin_fill_ms` already covers.
- **Block filters are built without copying every script.** The BIP158
  encoder took rust-bitcoin's `GcsFilterWriter`, which copies each output
  and spent script into an ordered set. It now hashes borrowed scripts,
  sorts them by hash, and drops exact duplicates; the filter bytes are the
  same. The live filter job also stopped cloning every transaction's
  cached prevouts before encoding, and reads the block's txids from the
  batch instead of hashing each transaction again for in-block spends.
- **Integer-keyed maps no longer compare every slot on a probe.** The
  identity hasher behind `U64Map`, `U64Set`, `FkMap`, `FkSet`, and
  `U32Map` returned the raw key. hashbrown filters a probe group by a tag
  from the top 7 bits of the hash, and every fk, height, and offset is far
  below 2^57, so all entries shared one tag and each probe compared every
  full slot in its group. The hash now keeps the key in the low 57 bits, so
  buckets and locality are unchanged, and puts a multiplied tag in the top
  7. These maps sit on every confirm thread (pins, stamp, structural spend
  checks).
  The structural spend check's set of `spent.body` slot offsets (8 bytes
  apart) now uses the spend-delta's stride hasher, which spreads those
  keys over every bucket instead of one in eight.
- **Each `header.head` overflow generation is twice the one before it.** A
  header lookup probes every generation, and equal-size generations made it
  linear in the header count past the first: 10,000 headers on the 64-slot
  test scale were 179 files per lookup. They are now 8. Older stores with
  equal-size generations open as before; no schema bump.
- **Archive planning finds a spend's block by binary search.** For every
  input of a batch, the plan checked whether its parent sits in the same
  block by scanning the batch's per-block ranges from the start. The
  ranges are in height order, so it now searches them.
- **An anchor ask reads the ordered queue only when it can matter.**
  `unproved_anchor` read every ordered hash once per checkpoint, so a long
  queue with several look-ahead checkpoints rescanned it on each
  `send_getheaders`. It now reads the queue only when a checkpoint sits at
  or above the queue front, from the back, and stops at the first hash that
  reaches the lowest such checkpoint.
- **Merged body peeks reuse one bounce buffer.** A merged page-span read
  allocated and zeroed a fresh buffer on every wave. Each wave now carves
  its merged spans from one per-thread buffer kept up to 1 MiB; a wave that
  needs more gets a buffer of its own and the kept one stays.
- **IBD's work-path maps hash block hashes in a few operations.** The
  in-flight, ordered, height, parent, known-header, header-fk, and body
  presence maps used std's SipHash over every 32-byte block hash. The
  per-second hygiene sweep visits every slot of the download window with
  two or three of those lookups, and assign does the same per request.
  They now fold the hash's four words with a rotate and a multiply.
- **IBD logs less and says more.** A spend checkpoint now writes one compact
  INFO summary; its detailed timing is DEBUG (category `store`) and is promoted
  to INFO only when the checkpoint is slow. Repeated checkpoint failures warn
  once a minute, with one recovery line.
- **`ibd: perf` is split by cadence.** The 5s line (category `ibd`) is a
  compact headline: pace, queues, stage totals, the spend window, and RSS. The
  full `ibd: perf_full` object is written every 30s or on a slow phase.
  `ibd: perf_full` gains a nested `spend` object with the checkpoint count,
  worst wall time, and `spend_notes_ram`.
- **The 5s RSS path no longer reads `smaps_rollup`.** `rss_kb` and the
  `RssAnon` / `RssFile` split stay fresh from `/proc/self/status`; the
  `smaps_rollup` fallback (and `Locked`) is on the 30s deep read.
- **A slow confirm phase warns on entry, once a minute, and on recovery**
  instead of every 5s.
- **Dropped duplicate `ibd: perf` keys:** the six `stamp_batch_*` child
  timers (use `arch_prep_*`), `plan_blks` / `plan_ms` / `plan_collect_ms` /
  `plan_head_ms` / `plan_cold_io_ms` (use the `lookup_*` names, including the
  new `lookup_blocks` / `lookup_ms` / `lookup_collect_ms` / `lookup_head_ms` /
  `lookup_cold_io_ms`), the duplicate `arch_prep_probe_ms` /
  `arch_prep_idx_ms` / `arch_prep_body_txid_ms`, the `_ns` twins of the
  `_ms` stage timers, `wf_body_store` / `wf_store_body_ms`,
  `rss_locked_kb`, the cumulative `uring_recover_n` /
  `uring_slow_drain`, and the duplicate age histogram
  (`arch_prep_age_hit_compact` plus `cdf7/15/31`; keep `cdf0`, `cdf3`, and
  `age_hit_n`). The full key list is `SAMPLE_FIELDS`.
- **IBD lookup no longer reads parents that are still in the confirm pipeline.** A lookup wave left out of its `tx.head` read only the transactions created in the same wave. A parent created by an earlier wave whose block was not yet connected was read, missed in every sealed `tx.head` segment, and then bound by load from in-flight anyway. Lookup now keeps the txids of the blocks it has decoded above its last drain+fence snapshot and leaves those parents out too. In a control sync, 30% to 50% of the txids lookup read between heights 400,000 and 850,000 were such parents. The set is one fixed table of 8 MiB: 2^20 slots, each a 40-bit tag of a txid hashed under a random per-process key and the height that created it. A slot is reused once its height has drained, a full bucket gives up its oldest create, whose spends are then read from `tx.head`, and every re-arm zeroes the table. The set binds nothing: load binds these parents from in-flight as before. Two txids with one tag in one bucket answer as one, so the set can hide a parent that is already on disk. Load then reads that one parent from `tx.head`, binds it, and logs a warning with the block hash, the height, and the parent txid. The table's heap counts toward the 1 GiB accounted heap the in-flight pin window is sized against. `ibd: perf_full` gains `lookup_undrained_skip` and `conf_pipe.undrained_bytes`. In 20-minute runs at heights 861,000 to 902,000 on a build where the write thread was no longer the limit, such parents were 12% of the txids lookup read, and leaving them out took the lookup thread's work from 25.1 ms to 21.8–23.0 ms per block. Those runs kept the set as one hash set with per-height txid lists; the table has not been timed on a node.
- **Confirm parent pins no longer pay a per-thread walk.** Each pin half
  (outs, layout) was an `ArcSwap` after its first publish. In `arc-swap` a
  store and a drop each visit every thread that has used the crate, so the
  IBD write thread paid that walk for every parent pin it filled and freed.
  A half is now one `Arc` behind a mutex. A publish and a pin drop cost the
  same at any thread count, and a pin keeps one snapshot per half instead of
  the first one plus the current one.
- **`create.loc` window decodes no longer start over at an overflow
  slot.** The 8-slot fast decode stopped at the first slot that needs an
  overflow row, and the scalar decode then redid the whole window. Now
  only that 8-slot chunk takes the scalar decode, and the fast decode goes
  on after it.
- **A `/metrics` scrape no longer walks the process page tables.**
  `process_resident_memory_bytes` read `/proc/self/smaps_rollup`, which
  the kernel builds by walking every mapped page, to report the resident
  size `/proc/self/status` already gives. It now reads `status` only.
- **The nightly image guard is a tested script.** The check that keeps
  `docker-publish` from moving `nightly` back to an older commit moved out
  of `release.yml` into `scripts/nightly-guard.sh`, with a self-test in
  `qc` that replays each way it broke before. No behavior change.
- **The overlay runner builds the node before it starts the meshes.** A
  broken build fails in seconds instead of after three minutes of daemons,
  and the TUN a journey binds no longer sits idle through the build.
- **`ibd: perf_full` shows what page-grouped body reads copy and drop.**
  `load_cold_range_read_kb` is what the confirm load's `txout.body` preads
  asked for (a merged group reads its whole page span, holes included);
  `load_cold_range_kept_kb` is what reached the parent jobs. The gap is the
  hole the grouping copied, the number a change to the merge limits needs.
  The write thread's `spent.body` slot peeks report the same pair as
  `meta_read_kb` / `meta_kept_kb`.
- **Merged spend-slot reads reuse the thread's kept buffer.** The write
  thread's `spent.body` peeks allocated and zeroed a fresh buffer for every
  merged group. They now read into the same per-thread bounce pool as the
  body peeks.
- **Confirm load borrows a pinned parent's output when scripts are not
  run.** Below the assumevalid milestone each spend of a batch-pinned parent
  took the pin's lock, cloned its outputs `Arc` twice, and looked the output
  up twice, then dropped the handle because no script job needed it. It now
  reads value and script under the batch's last-used outputs `Arc`. Script
  jobs still take their own handle.
- **`tx.head` insert overlaps confirm again.** `ibd-confirm-head` runs that insert beside structural work and Class C. `--datadir-hdd` still starts it after annotate. The insert stays outside the spindle hold.
- **Txid resolve walks sealed `tx.head` segments at the cost of the keys
  still open.** Each sealed segment allocated a candidate list per key of
  the whole wave (up to 256k) and made several passes over all of them,
  even when a handful were still unresolved. The walk now carries the
  unresolved key indices, a segment returns candidates only for keys that
  have some, and identity reads walk only those keys. The pick, fence, and
  fallback rules are unchanged.
- **A spend delta checkpoint merges into two buffers, not a map per
  page.** The merge read each touched page's committed record into its own
  copy, built a B-tree of its slots, laid the sealed notes over it, and
  encoded a new record per page: about seven allocations a page, and a
  mainnet checkpoint touches about 180,000 pages every 20 seconds in IBD.
  It now reads the committed records into one buffer sized from the
  directory and writes the merged records straight into one more, which
  the segment append writes from. Records that reclaim carries go into a
  buffer of their own, so they never regrow the merge's. Records are byte
  for byte what they
  were, and a committed record whose slots are out of order still refuses
  the merge. On a mainnet IBD, anonymous RSS stayed about 220 MiB higher
  for several seconds after each checkpoint while mimalloc held the freed
  memory; how much of that this removes needs the next IBD to tell.
- **Spend delta fold rounds reuse their buffers.** A checkpoint composes
  every folded page into one page buffer and every round into one `fold`
  buffer, emptied but kept after each round's copy. It used to allocate a
  4 KiB image per folded page and regrow the round's `fold` buffer (up to
  16 MiB) from empty every 4,096 pages: about 12.5 KiB asked of the
  allocator per folded page, now about 0.7 KiB. Peak RSS is unchanged:
  mimalloc already reused those blocks on the same thread.
- **The spend delta's in-RAM notes take about 100 MiB at the cap in IBD,
  peaking near 170 MiB while a checkpoint sorts, instead of several
  hundred, and a few hundred KiB at the tip.** Open
  notes were a SipHash map of pages, each holding a B-tree of its slots:
  about 34 bytes a note plus about 100 bytes a touched page. Open notes are
  now one hash map keyed by slot index, and a checkpoint sorts the notes it
  seals into a slot-ordered array of 16 bytes a note with a small
  key-range directory, read and merged in page order. Each checkpoint
  allocates the next window's map before the freeze, sized from the window
  it closes: after a window at the 2,000,000-note cap, a map of about
  68 MiB that holds the cap and a full write phase past it without
  regrowing. The freeze under the confirm exclusion swaps maps, and after
  a disconnect also copies the notes to judge them; the sort runs after
  it. The `store: spend delta` open and checkpoint lines gain
  `notes_ram=`, the RAM the notes allocate after the commit.
- **The confirm write thread reads a parent's spent range without a lock.**
  The spent-slot position of every spend was read through the pin's layout
  snapshot: a mutex and an `Arc` clone per spend, twice per spend per batch.
  Setting it cloned the whole layout, spender rels included. A create's
  spent range is fixed at its append, so the pin now holds it in a
  write-once cell beside the layout.
- **Library tests are out of production `src/` again.** The inline
  `#[cfg(test)]`
  modules that returned after the suite move now live in each production
  crate's `tests/suite` target, where the default `cargo test` runs them.
  Tests that only reached a private helper were dropped; the public journey
  already covered that line. `./scripts/src-test-modules.sh` fails `qc`
  when `#[cfg(...test...)]` returns to a production `src/` file;
  `rbitcoin-bench` is the exempt benchmark crate.
- **Store locator, spill, and durable-sidecar code has one implementation
  each.** `create.loc` and `seqsigwit.loc` share their append bookkeeping;
  the keys and postings spill directories share one protocol; and the RPC
  request envelope is parsed and answered once for both entry points.
- **Durable store sidecars fsync the parent directory.** Cold-progress,
  inclusion-HWM, phase-mark, and scripthash-occupancy writes now use the
  store's shared temp+rename helper instead of a private copy, so a renamed
  sidecar survives a power loss like the rest of the store.
- **Two equal-work tip siblings are scripted together.** A body already held
  for the same parent now runs its script wave beside the preferred block's,
  with each wave capped at half the worker pool while the other still claims.
  The first candidate whose strict scripts and write succeed is the tip; the
  other is parked. An invalid first block no longer delays a valid sibling for
  a full script wave.
- **A fully held, strictly heavier branch is connected before an expensive
  tip child** instead of after it.
- **A `tx.head` snapshot the store will not trust is not loaded.** At
  open, the footer generation and layout of the open tail snapshot are
  checked before its slots are allocated. A snapshot whose writer died
  before the footer commit no longer costs a zeroed table (128 MiB on
  mainnet) and a full read before it is dropped. A trusted snapshot is read
  straight into the table without zero-filling it first (#1717).
- **`tx.head` insert stores one slot.** A batch hops the live table and
  writes the empty slot. It does not copy the probe page.
- **Single confirmed-transaction lookups skip older index segments.** Once a
  transaction ID matches a row on the active chain, the lookup skips the
  remaining segments.
- **A `pub` item nothing names fails `qc`.** rustc does not report a dead
  `pub` item in a library crate, so the last caller could go and leave it
  behind. `./scripts/unused-pub.sh` now fails on a plain `pub` item in
  `src/` that no production file, test, or fuzz target names. Every such
  item on master is deleted, with the store's write-backend selector that
  no write path read and a directory-sync fault hook nothing could arm.
- **Script and witness XOR runs without a multiply per byte.** Every
  stored script and witness byte is XORed with a keystream whose mix byte
  came from a 64-bit multiply of its offset. Consecutive offsets differ by
  one, so the walk now adds the constant instead; the bytes are the same.
- **Mempool admission resolves a confirmed parent once per read and looks it
  up again if a block connects or disconnects during that read.**
