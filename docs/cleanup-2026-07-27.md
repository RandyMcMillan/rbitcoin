# Cleanup note (2026-07-27)

Reviewer-facing summary of a tidy pass: **delete dead weight**, **collapse dual
paths into one primary + OS modality fallback**, keep coverage and IBD roles.

## What went

| Item | Why |
|------|-----|
| `rbitcoin-query` dependency on `rayon` | Unused in source (scripts alone use rayon via `rbitcoin-consensus`). |
| Duplicated `verify_script_jobs` / `verify_script_job_refs` bodies | Single `verify_one_script_job` shared by owned and borrowed pool entries. |
| Standalone bulk `pread` implementations of `get_full_batch_at` / `get_meta_and_outputs_batch_at` | Both are thin wrappers over the shared **idx→body pipeline** (body-only jobs). One I/O path for confirm-style batch body decode. |
| `RBITCOIN_HEAD_RESOLVE=batch` force path | Pure algorithm A/B, not an OS modality. Primary remains streaming when uring is on; phased pipeline only when uring/stream fails. |

## What stayed (intentional)

| Complexity | Why it remains |
|------------|----------------|
| io_uring vs pread/mmap fallbacks (`RBITCOIN_IO_URING=0`, pipeline env off) | Host/OS modality — not prep-miss cold paths. |
| Streaming head-resolve vs phased `get_fk_by_txid_batch_phased` | Early-exit streaming when uring works; phased is the only non-stream bulk fallback. |
| Sticky / OutFifo / same-batch pin before store I/O | Hot-path cache hits; not dual algorithms for the same fact. |
| Role split (archive prep / writer / confirm load / scripts / write) | Documented concurrency; not over-abstraction. |
| Large tables (`tx_table`, IBD archive, electrum server) | Domain surface; further split is optional and out of this pass. |

## How to re-check

```bash
cargo test -p rbitcoin-store -p rbitcoin-query -p rbitcoin-consensus --lib
# optional: ./scripts/coverage.sh
```

Public store APIs `get_tx_full_batch_at` / `get_tx_meta_and_outputs_batch_at`
remain; they now share the pipeline implementation.
